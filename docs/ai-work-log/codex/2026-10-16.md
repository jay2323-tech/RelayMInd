### What was done

with exponential backoff/Retry-After, fallback time reservation, one JSON-envelope
repair, one final Plan/Review shape repair, and sanitized provider/engine diagnostics.

### How it works

Each adapter shares a deadline across network retries and envelope repair. Auth/404
errors do not retry. Fallback gets time reserved from the primary budget and applies
only to retryable failures. Model JSON and final-output schema errors are distinct:
provider repairs the calls-or-final envelope once; engine repairs final shape once
without repeating successful tools. Repair remains subject to call/context/time limits.
Run errors now retain safe stage/code/provider/HTTP metadata; server logs exclude raw
exception text, response bodies, headers, source data and credentials.

### What it affects

Temporary 429/503 errors need not terminate a run immediately. Groq requests include
a User-Agent, addressing Claude's suspected Cloudflare cause. One malformed Review
can be corrected. Use a fresh run ID after a terminal failure; previous failed runs
remain immutable history for retry semantics. Claude should fetch latest branch
before repeating the live Gemini/Groq run.
