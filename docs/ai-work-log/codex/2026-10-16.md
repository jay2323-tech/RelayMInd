## Pause, change, resume: launch and coding scenarios

**Requested by:** Jayanth. **Area:** Person 1 engine and shared integration.
**Branch / commit:** feat/agent-memory-engine; scenario follow-up after 7a37cb7.

### What was done

Added paused RunRecord status; conditional run/handoff checkpoint transitions;
pause_run/resume_run/explain_changes; a phase-based runner, two synthetic fixtures,
WhyChangedPanel and six real-database scenario checks. CLI supports --pause-after-plan.

### How it works

Pause only at an unclaimed saved handoff. Both run and handoff statuses and a run
snapshot change together. While paused, review cannot claim it. A fresh process
resumes; changed current decisions trigger deterministic stale-plan rejection and
one correction. Comparison uses saved original evidence and current records,
with real two-hop dependency traversal through fixture graph labels.

### What it affects

Launch: payment-enabled plan changes to free-tier-only. Coding: local password plan
changes to organization SSO/OIDC. Coding is plan adaptation, not source-code editing.
Claude must accept paused status and wire pause/resume/report endpoints/UI.
No task action is applied by the comparison. See ../../pause-change-resume.md.

### Problems found and how they were resolved

conditional checkpoint transition. Pausing active review could race: transition
requires pending handoff and awaiting_review run. Review already in progress is
refused, rather than pretending cancellation. Scenario decisions/tasks could be
confused with production tools: separate Scenario* labels and explicit model/platform
fixture labels are printed and documented.
