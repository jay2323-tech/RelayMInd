## 3. Two-tier memory design v1

**Requested by:** Jayanth · **Area:** shared (design for both teammates)
**Branch / commit:** `docs/memory-design` (local, uncommitted)

### What was done
Created `docs/memory-design.md`.

### How it works
Jayanth's idea: one memory for short-lived task state and one for things to remember.
Refined into:
- **Short-term** (Run, Handoff, Review, ProposedAction): stored in FalkorDB,
  scoped to one run, has a lifecycle status, never deleted.
- **Long-term** (Message, Episode, Decision, Procedure, Task): permanent.
- **Promotion gates** between them: approved actions change tasks; finished runs
  may become episodes; plans never become decisions automatically.
- Long-term split into **history** (Episode) and **truth** (Decision) so the
  supersession demo works.

Three refinements to the original idea and why:
1. Short-term must be persisted: otherwise the Reviewer cannot load the handoff
   independently and a restart loses it.
2. Expire instead of delete: keeps the audit trail for "why did the agent say that?"
3. Gate every promotion: otherwise agent guesses return later as facts.

### What it affects
Ownership table, interfaces and build order for both teammates.

### How it works
- **Decisions:** write-once nodes with a `topic`; no `status` property. A new
  version is created with `SUPERSEDES` edges to the decisions it replaces, only if
  they are current and in the same project/topic. Current = no incoming `SUPERSEDES`.
- **Tasks:** stable `Task` identity + immutable `TaskVersion` nodes linked by
  `HAS_VERSION` and `PREVIOUS`. Current = no incoming `PREVIOUS`.
- **Conflicts:** two or more current decisions on one `(project, topic)`. Reported,
  never resolved by timestamp/version/ID. Only a person resolves one, by recording a
  decision that supersedes every side.
- **Unverified features** each get a check before use: C-1 `WHERE NOT (pattern)`,
  C-2/C-3 `GRAPH.CONSTRAINT`. All queries now default to `OPTIONAL MATCH … count()`
  so nothing depends on unverified syntax.
- **Atomicity** of claims/approvals/creates: AT-1..AT-4 live tests with two
  independent OS processes, 100 rounds, pinned image. Until passed: single-process
  safety only.

### What it affects
- Shared fixture schema changed (Person 1 must know before merge): decisions now
  have `topic`, `supersedes` list, epoch-ms timestamps; tasks added.
- Contracts list new Person 2 functions (`record_decision`, `get_task`, …) and
  Person 1 functions (`claim_handoff`, `save_review`, …).
- No application code changed.

- `scripts/setup_graph.py` (indexes + unique constraints, platform labels only).

### How it works
- `record_decision` is one guarded Cypher query: the ID must be unused, every source must
  exist in the project, every replaced decision must be in the same topic and have zero
  successors; only then does it create the Decision, `SUPPORTED_BY` and `SUPERSEDES` edges.
  If the query returns no row, the code re-reads to give the precise reason (idempotent
  retry, ID conflict, unknown source, wrong topic, not current).
- `get_current_decisions` reads current decisions with `WHERE NOT (d)<-[:SUPERSEDES]-(:Decision)`
  (C-1 verified) and groups by topic in one snapshot: 1 → `current`, 2+ → `conflicts`.
