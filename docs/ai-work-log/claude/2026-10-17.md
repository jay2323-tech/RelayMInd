### How it works
- Propose: basis decisions must be current and not in conflict; records
  `(:ProposedAction)-[:TARGETS]->(:Task)` and `-[:BASED_ON]->(:Decision)`; changes nothing.
- Approve: (1) conflict on basis topics → `blocked_by_conflict`; (2) one guarded query creates
  TaskVersion v(n+1) `-[:PREVIOUS]->` v(n) and `-[:CAUSED_BY]->` action, copying the owner, only
  if v(n) is still current and no basis decision has a successor; (3) no row → re-read and
  record `stale` with the exact reason. Never reports success without a returned row.

### Problems found and how they were resolved
| Problem | Cause | Resolution |
|---|---|---|
| Every approval came back `stale`, even with nothing changed | On FalkorDB 4.22.1, `OPTIONAL MATCH (a)-[:BASED_ON]->(b)<-[:SUPERSEDES]-(:Decision) ... count(b)` returned no row when nothing matched | Bisected in a throwaway graph; replaced with the C-1-verified predicate `NOT (a)-[:BASED_ON]->(:Decision)<-[:SUPERSEDES]-(:Decision)`; noted in memory-design §5.2 |

The code never claimed success during the bug (it reported `stale`), which is the intended failure mode.
